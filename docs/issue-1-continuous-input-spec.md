# 连续输入确认候选修复规格

关联问题：`andelf/remi-znabc#1`  
日期：2026 年 11 月 8 日  
状态：已实现，正式回归通过  
基线：`861940e`；独立修复分支不包含工作区的补充字库改动

修复普通中文选词状态下继续输入字母的行为：先完成旧串的候选确认与提交，再让当前字母成为下一串的首字母。第一次空格仍只打开选单；没有后续输入时，最后一词仍需空格、数字或其他既有确认操作。

## 问题与依据

修复前，输入 `zhongguo → Space → d` 后，没有提交“中国”，原始编码变为 `zhongguod`，选单关闭。原因是 processor 将字母与 Esc、退格放在同一关闭选单分支中，随后交给 speller 追加旧编码。原有集成测试的 `letter did not resume editing` 断言还把 `ni32 → Space → h` 得到 `ni32h` 固定为预期；本次实现已替换该断言。

原版 `winabcnt.ime` 的选词分支在收到字母时，循环确认旧输入，随后重置输入，并将同一个字母交给新输入编辑函数。受控执行原版 x86 的 `d`、`n` 两个用例，均得到输出“中国”、新编码分别为 `d`、`n`。

| 依据 | 可支持的结论 |
| --- | --- |
| 原版 `0x60f0bb` 调用 `0x610c03` | 选词状态识别字母输入 |
| 原版 `0x60f0d5` 循环调用 `0x610ca4(0)` | 需要完成旧串转换，不能只确认一个候选段 |
| 原版随后调用 `0x60ffe2(1)`、`0x61020c` | 同一触发字母进入新串 |
| 修复前真实 Rime 逐键轨迹 | 续接旧编码，反馈可复现 |

原版动态验证从手工预置的完整候选状态开始，显示、学习和 Windows 输出边界使用替身。多段转换的循环有静态机器码依据，但没有 Windows 前端端到端验证。本规格对无候选、光标编辑和特殊模式的处理属于明确的 Rime 产品边界，不据此宣称恢复了原版完整状态机。

详细证据保存在仓库外的分析工作区：验证记录 `analysis/issue1-findings.txt`、原版执行结果 `analysis/evidence/issue1-verification.json` 和修复前 Rime 轨迹 `analysis/evidence/issue1-rime-trace.txt`。这些外部分析材料不随仓库分发；本规格保留关键地址、样本摘要和验证边界，正式回归随仓库提供。

## 修复范围

本次作为默认兼容行为修复，不增加开关。适用于普通空格打开的中文候选，包括拼音、音形、纯笔形、Tab 逐字和以词定字选单。

自动确认必须同时满足：

1. 中文模式，当前事件为无 Shift、Ctrl、Alt、Super 的小写字母 `a` 至 `z` 按下事件。
2. `znabc_selecting=true`，且原始输入非空。
3. `znabc_gbk=false`，当前串不属于 `i/I` 数量词或 `v` 临时英文及符号模式。
4. 光标位于原始编码末尾。
5. 当前段存在有效的选中候选，其消费范围满足 `segment.start < candidate._end <= #context.input`。

中文普通选单后的新字母 `i`、`v` 也属于触发字母。完成旧串后，它们必须按新输入规则进入数量词或临时英文，而不能拼到旧串上。

GBK 回车查询、已经进入的 `i/I` 和 `v` 模式、Shift／大写字母以及修饰键操作沿用既有行为。本次不实现 Issue 2 的自动切换英文，不调整词库、候选排序、学习策略或标点提交规则。

## 按键行为

下表中“当前候选”指当前高亮项，包括用户移动后的候选和附加成分规则预选项，不固定取候选数组的第一项。

| 当前状态 | 按键 | 修复后的行为 |
| --- | --- | --- |
| 正在编辑编码，未打开选单 | 小写字母 | 继续编辑当前编码 |
| 正在编辑编码 | 第一次 Space | 打开选单，不提交 |
| 普通选单，旧串可完整转换 | 小写字母 | 按当前候选逐段完成旧串，整体提交；当前字母启动新串 |
| 普通选单 | Space 或数字 | 保持现有的一段确认／数字选择行为 |
| 普通选单 | Esc | 退出选词并保留编码，随后可继续编辑 |
| 普通选单 | Backspace | 保持优先撤销上一组选字，否则关闭选单并删除编码的行为 |
| 普通选单 | 单引号 | 退出选词并作为隔音符继续编辑，不触发自动提交 |
| 选词标志已开，但没有有效候选 | 小写字母 | 保留旧编码，退出选词，追加当前字母；不提交 |
| 编码光标不在末尾 | 小写字母 | 按既有光标编辑路径处理，不自动提交 |
| GBK 或特殊输入模式 | 字母 | 保持对应模式的既有处理 |

核心示例：

| 按键序列 | 提交结果 | 当前编码与选单 |
| --- | --- | --- |
| `zhongguo → Space` | 无 | `zhongguo`，候选“中国” |
| 再按 `d` | 中国 | `d`，未打开选单 |
| 再按 `ifang → Space` | 此阶段无新增提交 | `difang`，候选“地方” |
| 再按 Space | 地方 | 编码清空 |
| `zhongguodifang → Space → d` | 中国地方 | `d`，未打开选单 |
| `zhongguoren → Space → d` | 中国人 | `d`，未打开选单 |

`zhongguo → Space → difang` 与 `zhongguodifang` 必须产生不同的转换边界：前者在输入 `d` 时结束“中国”这次输入；后者保留为一次完整输入，允许现有逐段转换与整串学习。

## 实现方案

### 在普通按键处理前完成旧串

修改 [znabc_processor.lua](../rime/lua/znabc_processor.lua)，增加局部辅助函数，负责在满足触发条件时逐段确认旧串。

入口放在现有 ASCII、释放事件、Alt／Super 和 Ctrl 处理之后，`i/I` 数量词及 `v` 模式分支之前。入口自行检查 Shift。这样旧串提交后，同一个按键可以继续经过当前函数中的新输入分支。

后续读取 `selecting`、`gbk`、`context.input` 时必须使用确认完成后的状态，不能继续使用确认前的缓存值。将原有“字母关闭选单”处理从 Esc／Backspace／单引号分支中拆开；未满足自动确认条件的普通字母仍需显式执行兼容的编辑回退。

### 通过 Rime 选择流程逐段确认

处理顺序如下：

1. 保存旧串初始长度，循环上限为该长度加一；当前方案编码最多 48 个字符，循环因此有界。
2. 检查当前段及选中候选的有效消费范围。
3. 调用 `context:confirm_current_selection()`，确认当前高亮项。
4. 若 `context.input == ""`，表示旧串已完成，退出循环。
5. 否则重新获取 composition、当前段和候选，继续确认下一段。
6. 当前段起点必须相对上一次确认前严格前进；若没有前进、确认返回失败、候选缺失或达到循环上限，停止自动确认，进入编辑回退。

不能使用输入总长度是否缩短判断进度。当前 Rime 分段选择在完成前会保留整串 `context.input`，实际进度体现为当前段 `start` 向后移动。

保持 `znabc_selecting` 开启直至旧串完成，使 translator 现有的 `select_notifier` 能生成下一段候选，并通过 `affix_selection.apply()` 恢复附加成分预选。下一次循环必须读取刷新后的实际高亮项，不能自行覆盖为索引零。

### 由现有提交回调完成提交和学习

通过 Rime 原有的确认、提交链路结束 composition，保留 `commit_notifier → Learning:commit()`。最终一段确认后，现有 express_editor 会完成旧串提交；隔离原型已经验证这一点。

不得提取候选文本后调用 `engine:commit_text()`，也不得在确认旧串前调用 `context:clear()`。这两种做法会绕过或破坏分段范围、学习记录与整串提交边界。不得用 `context:commit()` 强制提交包含未转换编码的 composition。

成功后确保 `znabc_selecting`、`znabc_gbk` 和 `znabc_single_character` 为关闭状态；允许现有 update 回调完成重置。旧串提交回调执行完毕前，不清空 `Learning.records`。本次不需要引入新的持久选项或独立学习逻辑。

### 同一个字母只处理一次

旧串完成后继续执行 processor 现有的新输入处理：

- 普通拼音字母走现有 speller，processor 返回 `2`。
- 新 `i` 进入数量词分支；由该分支接受按键并返回 `1`。
- 新 `v` 进入现有临时英文的起始路径。

不得递归调用 `engine:process_key()` 重放事件，也不得先 `push_input()` 同一个字母，再返回 `2` 让 speller 重复追加。

### 未能完成时回到编码编辑

如果入口处没有有效候选、光标不在末尾，或确认过程中遇到无法转换的剩余段，则不主动提交、不清空原始编码、不启动独立的新串。

关闭选词后，保留原始编码和 Rime 已保留的选择进度，将触发字母交给既有编辑路径一次。已经完成的内部段选择无需回滚；只要旧串尚未完整提交，就保留在同一次 composition 中。不得手动提交这些已选段。

例如 `ni32hao43 → Space → d`：第一段可以确认，但 `hao43` 没有有效候选，因此最终不得提交“你”或原始编码；编码保持为 `ni32hao43d`。用户可继续编辑或撤销。该回退在隔离原型中已验证，不属于对原版异常路径的等价声明。

## 学习与输入边界

[Learning:commit](../rime/lua/znabc/learning.lua) 根据完整 composition 的候选和消费范围记录使用次数与新词，本次继续使用这一机制。

| 情形 | 学习要求 |
| --- | --- |
| 一次输入 `zhongguodifang` 后由字母触发整串完成 | 允许按现有规则学习这次完整组合 |
| `zhongguo → Space → difang` | 两次输入分别学习，不得组合学习“中国地方” |
| 旧串已经人工选择部分字，随后由字母完成剩余段 | 保留人工选择，整串只按现有规则记一次；各段原有计数规则不变 |
| 确认过程中遇到空候选并回到编辑 | 不因本次触发记学习或使用次数 |
| 纯笔形或以词定字 | 保持现有学习排除规则 |

不能在辅助函数内调用 `store:remember()`，也不能在自动确认后再次补记使用次数。新输入开始时不得继承旧串的学习记录或逐字模式。
