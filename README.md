# 智能 ABC · Rime 复刻项目

当前可安装版本：**0.2.2**。在 Rime 上实现原样本的基础拼音、音形后缀、纯笔形输入，支持两阶段选字、`Tab` 逐字选择、`[` / `]` 以词定字、`v` 前缀临时英文输入，以及分级用户词库和自动造词。

## 安装测试

前提：已安装 Rime 前端，且包含 **librime-lua**。本方案是 Lua 插件与数据包，无需编译 C++。

使用 `dist/rime-znabc-0.2.2.zip`，解压后进入里面的 `rime-znabc-0.2.2` 目录。
安装器需要 Python 3.8 或以上，仅使用标准库。下面任选符合你的前端的一条命令：

```powershell
py install.py --user-dir "$env:APPDATA\Rime"
```

```sh
python3 install.py --user-dir "$HOME/Library/Rime"
```

```sh
python3 install.py --user-dir "$HOME/.local/share/fcitx5/rime"
```

```sh
python3 install.py --user-dir "$HOME/.config/ibus/rime"
```

以上依次对应小狼毫、鼠须管、fcitx5-rime、ibus-rime 的常见用户目录。
若曾修改过用户目录，以前端菜单打开的“用户文件夹”为准。
安装器会复制方案、Lua 和数据，向已有方案列表追加 `znabc`，并备份覆盖文件到用户目录的 `.znabc-backups/`。
可以先加 `--dry-run` 查看计划。复杂的 `default.custom.yaml` 格式会明确报错并停止写入；此时使用 `--no-enable`，手动加入方案列表。

完成后在前端执行 **重新部署**，打开方案选单，选 **智能 ABC · 复刻**。

### 没有 Python 时手动安装

把安装包 `rime/` 里面的以下三个项目复制到 Rime 用户目录根部：

```text
znabc.schema.yaml
lua/
znabc_data/
```

`lua/` 与已有同名目录合并。模块放在 `lua/znabc/`，不需要修改已有 `rime.lua`。
在 `default.custom.yaml` 的现有 `patch:` 下添加以下两行；已有同名补丁键时，应直接在现有方案列表中追加 `schema: znabc`：

```yaml
patch:
  "schema_list/@next":
    schema: znabc
```

不要把第二个 `patch:` 粘贴到已有 `patch:` 的文件末尾。重新部署后切换方案。

## 键位与测试样例

| 按键 | 当前行为 |
| --- | --- |
| 字母 | 输入拼音或声母简拼 |
| `1..8` | 编码阶段输入形码，包括纯数字笔形输入；选单打开后选择对应候选 |
| `'` | 显式音节分隔 |
| 空格 | 第一次结束编码、打开选单，不上屏；选单打开后确认当前高亮候选 |
| `1..9`（选字阶段） | 选择当前页对应候选；无对应候选时保持选单 |
| `Tab`（拼音选单打开时） | 切换整词优先／逐字选字，保留输入编码 |
| 词编码后加 `[` / `]` | 以词定字：取候选词的首字／末字；空格打开选单后选择 |
| `Ctrl+1..9` | 选单打开后也可选择当前页对应候选 |
| 上下方向键 | 移动候选高亮 |
| `PageUp` / `PageDown`、`-` / `=` | 翻页 |
| `Backspace` | 删除编码；选单打开时先返回编码阶段 |
| `Esc` | 选单打开时关闭选单、保留编码；编码阶段取消当前输入 |
| 单击 `Shift` | 切换中西文；有编码时先提交编码 |
| `v` + 英文字母或数字 → 空格 | 直接上屏去掉首个 `v` 的内容，保留大小写，不切换中西文 |
| `Ctrl+Delete`（选单打开时） | 删除高亮用户词；基础词只清除个人使用记录，不删除基础词条 |

编码阶段不显示候选，数字不用于选字。按空格后才产生候选，数字不再追加形码。
选单打开后输入字母或分隔符会返回编码阶段继续输入；没有候选时，空格不会把原始编码上屏。
输入句点等中文标点仍可确认当前首选并输出标点。
临时英文示例：`vlove` → 空格直接上屏 `love`，无需第二次空格；`vLove` → 空格上屏 `Love`。
临时英文支持退格修改和 Esc 取消，提交后继续中文输入。单独 `v` → 空格上屏 `v`，`vv` → 空格也上屏 `v`。

建议实际安装后测试：

| 输入 | 预期 |
| --- | --- |
| `nihao`、`ni32hao63`、`ni3hao6` | 第一次空格显示首选“你好”，再按空格或 `1` 上屏 |
| `nihao32`、`ni32hao43` | 不应出现词条“你好”；可先选前面的单字，后面的编码继续保留 |
| `shi81` | 包含“时、是、匙”；排序由原始字频及内部码决定 |
| `ni32` | 包含“你、倪、伲”；形码后缀不保证唯一候选 |
| `ke18` / `ke15` | 前者包含“可”，后者不包含“可” |
| `3235` | 空格后候选依次“仂、你、仍”，按 `2` 选择“你” |
| `ni32` → 空格 → `2` | 上屏“倪”，数字 `2` 不追加到编码 |
| `xian` / `xi'an` | 前者按 xian 查询；后者显示 xi、an 两个音节 |
| `changan` / `chang'an` | 前者切 chan + gan；后者切 chang + an |

候选词只覆盖输入前半段时，选中后保留剩余编码并返回编码阶段；再次按空格打开剩余编码的选单。本版不自动把多个短词拼成一个整句候选。

如果整词候选里没有需要的词，例如 `fuke` 只有“复课、妇科”，可以空格后按 `Tab` 改为逐字选择。
先在 `fu` 的候选中选择“复”（可翻页），再次空格打开 `ke` 的候选，选择“刻”，整词上屏“复刻”。
逐字模式在本串编码的剩余部分继续生效，全部上屏或清空后恢复整词优先。
选单中再按 `Tab` 可恢复剩余编码的整词候选。该切换不会改变默认最长词匹配和原始排序。

### 以词定字

在完整词编码末尾加 `[` 取首字，加 `]` 取末字。例如：

| 输入 | 预期 |
| --- | --- |
| `shijie[` → 空格 → 空格或 `1` | 从“世界”取“世” |
| `shijie]` → 空格 → 空格或 `1` | 从“世界”取“界” |
| `fuke]` → 空格 | 基础词“复课、妇科”分别提供“课、科”；选择对应数字上屏 |

候选旁显示来源词，顺序沿用词候选排序；结果字相同时只保留排序靠前的来源。
已学习的用户词同样参与，例如收录“复刻”后，`fuke]` 也能取“刻”。
形码后缀仍有效，例如 `ni32hao63]` 取“好”。
也可先打开普通词选单，再按 `[` / `]` 直接转换候选；再次按方括号替换原后缀，退格删除后缀后可重新空格选词。
以词定字时 `Tab` 不切换逐字模式。只有覆盖后缀前全部编码的词才参与，单音节或没有完整匹配词时无候选，空格不会提交原始编码。
取字操作不增加来源词使用次数；包含取字的一次输入不自动造词，也不更新个人使用记录。对取出的字按 `Ctrl+Delete` 不删除来源词。
临时英文 `v` 模式中的方括号保持原样，例如 `vlove]` → 空格输出 `love]`。

反馈时请提供：前端及系统、原始按键串、候选顺序、实际上屏结果、期望结果；出错时附前端日志中的 `znabc` / `Lua` 信息。

## 自动造词与分级用户词库

默认开启自动学习。一次输入完整编码，分几次选择字或短词，最后整串编码全部转换并上屏时，自动收录基础词库里没有的 2～9 字组合。
不同次已经上屏的独立输入不会合并；取消输入、直接提交原始编码、英文及纯笔形输入不用于造词。

例如首次输入 `ni32ni32`：空格 → `2` 选择“倪”，再次空格 → `2` 选择第二个“倪”，最终上屏“倪倪”。
再次输入 `ni32ni32`，空格后即可整词选择“倪倪”；全拼 `nini` 和简拼 `nn` 也能查询，字形后缀仍参与过滤。
基础词库已有其他同音词时，可用 `Tab` 逐字组合，例如上述“复刻”；完成后同样自动收录，下次 `fuke` 可以整词选择。
分段选择期间仍处于同一次编码转换，按数字只选择一段，下一段需要再次空格打开选单。

| 级别 | 规则 |
| --- | --- |
| 基础词 | 原始词库保持只读，个人使用次数单独记录 |
| 临时新词 | 收录时后续使用次数为 0，候选注释显示 `〔新词 0/3〕`；每次完整提交后增加一次 |
| 常用用户词 | 临时词后续选用 3 次后晋升，注释显示 `〔常用〕`，不自动淘汰 |

临时词默认容量 2,000 条，满时优先淘汰使用次数少、较久未使用的词。每次收词和计数更新都会写入独立的 `znabc_user.userdb/`，重新部署和更新方案不覆盖该数据库。
保存实际选中的内部字码，保留多音字的读音，不将形码后缀当成读音编码。

候选先按最长匹配词长选择；同长度依次考虑常用用户词、已有个人选择记录的基础词、临时新词、其他基础词。
同级按使用次数、最近使用时间排序，其后保留基础权重及原顺序；学习项与相同内部字码的基础项合并。
此分级排序是本版的产品规则，并不声称完全复刻原 ABC 的历史输出和合成权重。

在 Rime 方案选单中切换：

- **冻结学习**：继续查询用户词，但不自动新增或累计使用次数；主动删除仍可用。
- **基础词库**：停用用户词和个人排序，同时停止学习，恢复基础匹配与排序。
- **自动学习 / 用户词库**：恢复相应功能。默认每次加载本方案启用。

选中误收词后按 `Ctrl+Delete` 删除，同时保存禁止再次自动收录的标记。删除基础词候选仅清除其个人记录并保存同样标记，基础词仍可查询。
删除标记针对该读音下的内部字码序列；当前没有界面用于撤销标记或手动固定词条。
数据库使用 librime-lua 的 LevelDb 接口；接口不可用或打开失败时，输入法退回基础查询并记录日志。数据库写入失败也会记入前端日志。
暂未实现用户词跨设备同步、手动固定词及原版单字选择历史。

可在 `znabc.custom.yaml` 中调整以下配置，重新部署生效：

```yaml
patch:
  "znabc/learning/min_length": 2
  "znabc/learning/max_length": 9
  "znabc/learning/promotion_uses": 3
  "znabc/learning/temporary_capacity": 2000
```

已有该自定义文件时，将条目合并到现有 `patch` 中。临时容量在收录新词时执行淘汰；缩小配置不会立即清理整个已有词库。

## 数据与兼容范围

使用已有逆向结果直接生成：

- 75,705 条基础词记录，保留原始内部字码、权重和词库顺序。
- 7,231 条有读音的单字记录，包含多音字的独立读音码。
- 7,787 条正常基础笔形关系；不可输入的异常标记不进入运行数据。
- 拼音形码后缀使用专用摘要表，不以完整笔形码前两位替代。
- 单字频度从原 OVL 的频度区恢复，未覆盖的字按原函数回退值处理。
- 词候选先取最长有结果的词长，同词长按权重降序、同分保留词库顺序。
- 单字按权重降序，同分按内部字码升序；纯笔形按原表顺序。

本版本接入基础词库和独立用户词库。扩展字库、原版历史选择算法、特殊输入模式及完整原界面交互尚未接入。
默认开启学习，个人记录会影响词候选排序；切换“基础词库”可恢复无学习时的原始候选顺序。
本仓库包含输入法源码及生成的基础词库，不包含原始程序、逆向分析工作区或个人用户词库。

## 开发

目录结构：

```text
rime/znabc.schema.yaml       Rime 方案与键位
rime/lua/znabc_processor.lua 编码与选字状态、空格和数字按键
rime/lua/znabc_translator.lua 候选区间、预编辑与 Rime 适配
rime/lua/znabc/parser.lua    移植的连续输入解析
rime/lua/znabc/engine.lua    查询、过滤和排序
rime/lua/znabc/dictionary.lua 数据加载与分桶缓存
rime/lua/znabc/user_dictionary.lua 用户词持久化、晋升、淘汰和删除标记
rime/lua/znabc/learning.lua   单次编码的提交验证与收词
tools/build_data.py         从已有样本生成数据
tools/install.py            复制安装及配置追加、备份
tools/package.py            构建完整安装 ZIP
tests/                      Lua、原 x86 对照和真实 Rime API 测试
```

仓库已包含运行所需的基础词库。克隆后可以直接安装：

```sh
python3 tools/install.py --user-dir "$HOME/Library/Rime"
```

在鼠须管菜单执行“重新部署”后选择“智能 ABC · 复刻”。其他平台的用户目录见安装测试章节。

构建完整安装包：

```sh
python3 tools/package.py
```

仅在重新提取基础词库时运行 `python3 tools/build_data.py`；该工具会引用外部工作区的 `analysis/znabc_formats.py` 和已解压的样本，这些文件不在本仓库中。日常开发、安装、打包和 Lua 内核测试直接使用仓库中的词库；输入法运行不依赖 Python。
词库按前两字首字母分成 516 个桶，按需读取并缓存，避免每次按键全表扫描。

有 Lua 5.4 时执行内核测试：

```sh
lua5.4 tests/test_engine.lua .
lua5.4 tests/test_learning.lua .
python3 -m unittest discover -s tests -p 'test_installer.py' -v
```

原 x86 对照测试还需要已有的 `uv`、Unicorn 和上级分析文件：

```sh
uv run --no-project --python /usr/bin/python3 --with unicorn python tests/test_native_compat.py --lua /absolute/path/to/lua5.4
```

`tests/rime_smoke.cc` 通过真实 `librime` 与 `librime-lua` 测试部署、逐键输入、选词上屏、部分消费、西文模式和学习。每次完整测试必须使用全新测试用户目录，复制 `tests/fixtures/default.yaml` 为该目录的 `default.yaml`，并使用安装器安装方案。
同一测试目录随后再次运行程序并附加 `--learning-reload`，验证常用词和删除标记在进程重启后保留。Linux 下编译需要 Rime 开发头文件及库。
本工作区的依赖只解压在 `.cache/runtime/`，没有改动系统 Rime 安装。
验证范围与版本记录见 `VERIFICATION.txt`。Windows / macOS 前端的实际界面仍由本轮人工安装验证。
